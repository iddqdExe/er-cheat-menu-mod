# ER Multitool Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Создать устанавливаемую DLL с визуальным меню для выдачи предметов, изменения персонажа, открытия карты/благодатей и применения наборов.

**Architecture:** Интерфейс создаёт типизированные команды, которые проверяет и выполняет отдельный адаптер Elden Ring. Рендеринг, каталог, сохранение настроек и доступ к игре разделены. Исходная CT служит справочником; среда Cheat Engine не требуется при работе мода.

**Tech Stack:** Windows x64, C++20, CMake, MSVC, Dear ImGui, DirectX 12. Версии сторонних библиотек фиксируются при добавлении после проверки первичных источников и лицензий.

**Spec:** [Проект мода](../specs/2026-10-12-er-multitool-design.md).

## Global Constraints

- Целевая версия исполняемого файла: `2.7.1.0`; неизвестная версия отключает изменение игры.
- DLL загружается через существующий загрузчик; имеющиеся графические библиотеки не заменяются.
- Русский интерфейс, локальные иконки, клавиша Insert по умолчанию, переназначение и масштабирование.
- Первая версия рассчитана на мышь и клавиатуру и существующий офлайн-запуск.
- Извлечённые игровые ресурсы, CT и сохранения не публикуются в Git.
- Успешная компиляция не заменяет проверку действий внутри игры.

## Review Focus

1. Перезагрузка мира или смена персонажа между подготовкой и исполнением команды: устаревшая команда отклоняется.
2. Несколько совпадений сигнатуры или повреждённая цепочка указателей: запись запрещена.
3. Resize, потеря устройства и существующий графический мод: корректное освобождение ресурсов, отсутствие зависания GPU.
4. Неполный каталог, отсутствующая иконка или неверный уровень улучшения: заглушка и отказ от неподдерживаемой операции.
5. Частичное применение набора и повторная выдача: точный отчёт по действиям без ложного сообщения о полном успехе.

## Task 1: Карта переноса и проверяемые данные CT

**Files:** `tools/inspect-table.ps1`, `docs/ct-porting-matrix.md`, `tests/fixtures/minimal.CT`, `tests/inspect-table.tests.ps1`.

**Interfaces:** `inspect-table.ps1 -InputPath <CT> -OutputPath <JSON>` извлекает ID, путь записи, тип, символы и зависимости; не исполняет Lua/Assembler. Выход предназначен для локального исследования, не для исполнения игрой.

- [ ] Написать тест на вложенные записи, одинаковые названия с разными ID и невалидный XML; ожидаются сохранённая иерархия и диагностируемый отказ.
- [ ] Запустить тест до реализации и убедиться в ожидаемом отказе из-за отсутствующего инструмента.
- [ ] Реализовать разбор XML и отчёт зависимостей с отключённым разрешением внешних сущностей.
- [ ] Проследить и задокументировать GameDataMan, ItemGib/itembuffer, AddSoul, карту и благодати: сигнатуры, аргументы вызовов, зависимости, ограничения. Для каждой функции указать статус переноса.
- [ ] Запустить `pwsh -File tests/inspect-table.tests.ps1`; проверить реальную CT; закоммитить инструмент и матрицу, исключив оригинальную CT и её полную выгрузку.

## Task 2: Ядро команд и адаптер версии

**Files:** `CMakeLists.txt`, `CMakePresets.json`, `src/core/commands.hpp`, `src/core/validation.cpp`, `src/game/memory.hpp`, `src/game/memory.cpp`, `src/game/version_profile.hpp`, `tests/core_tests.cpp`, `tools/build.ps1`.

**Interfaces:** `SessionToken` идентифицирует текущую игровую сессию; `Command` содержит token и variant из `GiveItem`, `SetAttributes`, `SetRunes`, `SetWorldFlags`; `Result` содержит статус и объяснение. `find_unique(span<const byte>, Pattern)` возвращает единственное смещение либо ошибку. `validate(const Command&, const GameSnapshot&, const Catalog&) -> Result` не изменяет память.

- [ ] Написать тесты поиска сигнатур: единственное совпадение, отсутствие, два совпадения, маски, усечённые данные. Добавить тесты устаревшего SessionToken, неверной версии и недопустимых параметров команды.
- [ ] Настроить сборку тестов, зафиксировать ожидаемый отказ до реализации.
- [ ] Реализовать поиск, проверку команд и чтение профиля версии; границы памяти проверять до чтения. Значения и связи характеристик подтвердить исследованием Task 1.
- [ ] Запустить configure/build и `ctest --test-dir build --output-on-failure`; все проверки должны пройти. Закоммитить.

## Task 3: DLL, рендеринг и оболочка меню

**Files:** `src/mod/dllmain.cpp`, `src/mod/runtime.cpp`, `src/render/dx12_overlay.cpp`, `src/render/input.cpp`, `src/ui/theme.cpp`, `src/ui/menu.cpp`, `src/config/settings.cpp`, `tests/settings_tests.cpp`.

**Interfaces:** `Overlay::initialize`, `Overlay::render`, `Overlay::shutdown` управляют жизненным циклом; `Menu::draw(const GameSnapshot&, CommandQueue&)` не пишет в память игры. `Settings` хранит клавишу, масштаб, избранное и последний раздел.

- [ ] Проверить официальные примеры ImGui/DX12 и механизм совместимого перехвата; закрепить версии зависимостей и уведомления об их лицензиях.
- [ ] Добавить тесты настроек: отсутствующий/повреждённый файл, неизвестная версия, недопустимый масштаб и клавиша. Подтвердить первоначальный отказ, реализовать чтение с корректными значениями по умолчанию и атомарную запись.
- [ ] Реализовать минимальный DllMain без тяжёлой работы под loader lock; отложенную инициализацию, диагностику и обратимый перехват.
- [ ] Реализовать DX12 descriptor heaps, frame contexts, fence-синхронизацию, resize и обработку потери устройства. Подтвердить правильную command queue, не выбирать её произвольно.
- [ ] Создать русскую оболочку с боковой навигацией, иконками с подписями, статусом подключения, читаемым шрифтом с кириллицей и масштабированием.
- [ ] Проверить Insert/Escape, захват ввода только при открытом меню, отсутствие управления персонажем при вводе в поля, повторное открытие и изменение размера окна. На действующей графической конфигурации проверить отсутствие конфликтов и записать результаты. Закоммитить.

## Task 4: Каталог и изображения

**Files:** `tools/import-catalog/`, `src/catalog/catalog.hpp`, `src/catalog/catalog.cpp`, `src/catalog/icon_cache.cpp`, `src/ui/items.cpp`, `tests/catalog_tests.cpp`.

**Interfaces:** `ItemRecord` содержит игровой ID, icon ID, русское/английское название, категорию, DLC, ограничения количества и улучшения. `Catalog::search(const ItemFilter&) -> vector<ItemId>`; `IconCache::get(IconId)` возвращает готовое изображение или заглушку.

- [ ] Проверить инструменты извлечения из установленной игры и их поддержку версии; альтернативные источники изображений сопоставлять по ID с учётом условий использования. Не скачивать ресурс только на основании совпадения названия.
- [ ] Написать тесты поиска на русском/английском, неизвестного ID, неполной записи, отсутствующей иконки и несовместимого улучшения; подтвердить отказ до реализации.
- [ ] Реализовать локальный импорт с отчётом покрытия основной игры/DLC, валидируемую схему каталога и ограниченный кеш текстур.
- [ ] Реализовать сетку, категории, поиск, фильтры, избранное, недавние, правую карточку и форму выдачи. Без адаптера выдача явно недоступна.
- [ ] Запустить тесты; проверить реальный большой каталог, прокрутку, отсутствие сетевых обращений во время игры, читаемость на 1080p и при повышенном масштабе. Закоммитить.

## Task 5: Реальные игровые операции

**Files:** `src/game/adapter.hpp`, `src/game/adapter.cpp`, `src/game/item_grant.cpp`, `src/game/character.cpp`, `src/game/world_flags.cpp`, `src/ui/character.cpp`, `src/ui/world.cpp`, `tests/adapter_tests.cpp`.

**Interfaces:** `GameAdapter::snapshot() -> GameSnapshot`; `GameAdapter::enqueue(Command) -> RequestId`; `GameAdapter::drain_on_game_thread()` выполняет ограниченное число команд в подтверждённой безопасной точке; `GameAdapter::result(RequestId) -> Result` возвращает проверенный итог.

- [ ] Написать тесты на поддельном backend: недоступный персонаж, смена token после enqueue, неверная сигнатура, ошибка вызова и частичное применение флагов. Подтвердить отказ до реализации.
- [ ] Перенести подтверждённые Task 1 вызовы и структуры отдельно для выдачи, рун, характеристик и флагов мира. Проверять контекст повторно при исполнении; не использовать произвольный поток рендеринга для игровых вызовов.
- [ ] Добавить формы текущих/новых характеристик, рун и усилений DLC; список регионов, карт и благодатей с точным состоянием и предварительным просмотром массовых изменений.
- [ ] Выполнять реальное тестирование на отдельном сохранении с резервной копией, сделанной при отсутствии записи игрой: один обычный предмет, улучшенное оружие, руны, характеристики, карта, одна благодать; затем массовые операции и DLC.
- [ ] Проверить результаты повторным чтением и средствами самой игры; ошибки не выдавать за успех. Зафиксировать ограничения неподтверждённых функций, запустить все автоматические тесты, закоммитить.

- [ ] Написать тесты повреждённых наборов, неизвестных ID, смены версии схемы, повторной выдачи и частичного отказа; подтвердить отказ до реализации.
- [ ] Реализовать сохранение, переименование, загрузку и предварительный просмотр наборов. Показать предупреждение о повторной выдаче в контексте конкретного действия.
- [ ] Создать пакет DLL/конфигурации/инструкций и проверяемый установщик в отдельный каталог `mods/ERMultitool`; корневую DLL разместить по требованиям загрузчика. Не перезаписывать чужие моды; предусмотреть удаление только собственных файлов по манифесту.
